# แผนอัปเกรดระบบตรวจจับจอ E-Board อัตโนมัติด้วย MAC Address (วง 10.80.80.*) และระบบอัปเดตเซิร์ฟเวอร์อัตโนมัติ

แผนการพัฒนานี้แก้ปัญหาทั้ง 3 ข้อที่ผู้ดูแลระบบต้องการ ได้แก่ การทำให้ระบบตรวจเจอจอ E-Board ทันทีที่เปิดเครื่องโดยไม่ต้องกดสแกนเครือข่ายเอง, การล็อกให้สแกนและจับคู่เฉพาะเครื่องที่มีในระบบผ่าน MAC Address ในวง `10.80.80.*` เท่านั้น และการซิงก์อัปเดตโค้ดจาก AI Studio ลงเครื่องเซิร์ฟเวอร์จริง (`https://eboard.spsm-it.cc/`) อย่างรวดเร็ว

### User Review & Critical Decisions

> [!IMPORTANT]
> กรุณาตรวจสอบแนวทางการทำงานทั้ง 3 ส่วนด้านล่าง หากตรงตามความต้องการ สามารถกดปุ่ม **Proceed** เพื่อให้ระบบเริ่มเขียนโค้ดและสร้างสคริปต์อัปเดตได้ทันทีครับ

- **Confirmed Decision 1 (ตรวจจับจอเปิดใหม่อัตโนมัติความเร็วสูงโดยไม่ต้องกดสแกน)**: เพิ่มระบบ **Background ARP & MAC Discovery** ในเซิร์ฟเวอร์ ให้กวาดกระตุ้น ARP เฉพาะวง `10.80.80.1 - 10.80.80.254` เบื้องหลังอัตโนมัติทุกๆ 15 วินาที (เมื่อมีจอที่ยัง OFFLINE) เพื่อให้ตาราง ARP ของ Windows รู้จัก IP ใหม่ของจอทันทีที่เสียบสายแลน/ต่อเน็ต โดยไม่ต้องรอให้คนมากดปุ่มสแกนเครือข่าย
- **Confirmed Decision 2 (สแกนเฉพาะเครื่องที่มีในระบบ ยึด MAC Address เป็นหลักในวง `10.80.80.*`)**: ปรับทั้งระบบตรวจสอบเบื้องหลังและหน้าต่างสแกนเครือข่ายให้ใช้โหมด **"จับคู่เฉพาะอุปกรณ์ที่มีในระบบด้วย MAC Address (วง 10.80.80.*)"** เป็นค่าเริ่มต้น โดยจะนำ MAC Address ที่ตรวจพบในวง `10.80.80.*` ไปเทียบกับฐานข้อมูลที่มีอยู่ หากตรงกันจะอัปเดต IP ใหม่และเปลี่ยนสถานะเป็น `ONLINE` ทันที และไม่ดึงเครื่องแปลกปลอม (เช่น มือถือหรือโน้ตบุ๊กครู) เข้ามาปน
- **Confirmed Decision 3 (วิธีอัปเดตจาก AI Studio ลงเครื่องจริงให้ไวที่สุด)**: เพิ่มฟีเจอร์ **1-Click System Update (ผ่าน GitHub Sync + ปุ่มอัปเดตในหน้าตั้งค่า / สคริปต์ `update-windows.bat`)** เพื่อให้เมื่อแก้ไขโค้ดบน AI Studio เสร็จ สามารถกดซิงก์และสั่งให้เครื่องเซิร์ฟเวอร์ดึงโค้ดใหม่ Build และรีสตาร์ท PM2 อัตโนมัติโดยที่ข้อมูล `devices.json`, `settings.json` และ `logs.json` ไม่ถูกทับ

### 1. Overview & Core Concept

- **What It Does**:
  1. **สาเหตุที่เดิมต้องกดสแกนเครือข่ายก่อนถึงจะเจอจอ**: เพราะจอ E-Board บางเครื่องเปลี่ยน IP ไปตาม DHCP ในวง `10.80.80.*` ซึ่ง Windows Server จะไม่รู้ว่า MAC Address นั้นย้ายไปอยู่ IP ไหนจนกว่าจะมีการ Ping ไปยัง IP ใหม่นั้น ระบบใหม่จึงเพิ่มตัวกวาดกระตุ้น ARP อัตโนมัติในวง `10.80.80.*` อยู่เบื้องหลังตลอดเวลา
  2. **การจับคู่ด้วย MAC Address เฉพาะเครื่องในระบบ**: ระบบจะตรวจสอบ MAC Address จากตาราง ARP ในวง `10.80.80.*` เทียบกับรายการอุปกรณ์ที่มีในระบบเป็นหลัก ทันทีที่ตรงกันจะอัปเดตเลข IP ปัจจุบันและเปลี่ยนสถานะเป็นออนไลน์ภายในไม่กี่วินาที
  3. **การอัปเดตระบบสู่ `https://eboard.spsm-it.cc/`**: เนื่องจาก AI Studio รันอยู่บน Cloud ของ Google ส่วน `eboard.spsm-it.cc` รันอยู่บนคอมพิวเตอร์ในโรงเรียน การเชื่อมให้ซิงก์กันไวที่สุดทำได้โดยเชื่อม GitHub บน AI Studio แล้วใช้ปุ่ม **"อัปเดตระบบจาก GitHub"** บนหน้าเว็บ (หรือดับเบิลคลิกไฟล์ `update-windows.bat`) เพื่อให้เซิร์ฟเวอร์ดึงโค้ดใหม่และรีสตาร์ทเองในคลิกเดียว
- **Target Audience / Persona**: ผู้ดูแลระบบเครือข่ายและไอทีของโรงเรียนที่ดูแลกระดานอัจฉริยะ E-Board ทั้งหมดในวงแลน `10.80.80.*`
- **Key Value**: จอเปิดปุ๊บขึ้นสีเขียว (`ONLINE`) ปั๊บภายใน 5–15 วินาทีแม้เลข IP จะเปลี่ยนไปตาม DHCP โดยไม่ต้องกดสแกนหาเอง และอัปเดตโปรแกรมเวอร์ชันใหม่ได้โดยข้อมูลเดิมไม่หาย

### 2. User Experience & Visual Design

- **Key User Flows**:
  1. **การทำงานอัตโนมัติเมื่อเปิดจอ E-Board**:
     - เมื่อครูเปิดจอ E-Board ในห้องเรียนและจอได้รับ IP ในวง `10.80.80.*`
     - เซิร์ฟเวอร์ส่ง Fast ARP Probe ในวง `10.80.80.*` เบื้องหลัง -> ดึงเลข MAC Address มาเทียบกับอุปกรณ์ที่มีในระบบ -> อัปเดต IP ให้ตรงกับปัจุบัน -> แสดงสถานะ `ONLINE` บนหน้า Dashboard ทันที
  2. **หน้าต่างสแกนเครือข่ายโฉมใหม่ (MAC-Matched Scanner เฉพาะวง `10.80.80.*`)**:
     - เมื่อกดปุ่ม **"สแกนเครือข่าย"** จะมีโหมดเริ่มต้นคือ **"สแกนจับคู่เฉพาะเครื่องที่มีในระบบด้วย MAC (10.80.80.1 - 254)"**
     - แสดงผลเฉพาะจอ E-Board ที่มีในระบบที่ตรวจพบ MAC Address พร้อมบอกเลข IP เดิม -> เลข IP ใหม่ และปุ่มกดซิงก์อัปเดตทันที
  3. **การกดอัปเดตระบบจากหน้าเว็บ (หรือสคริปต์คลิกเดียว)**:
     - ในเมนู **"ตั้งค่าระบบ" (Settings)** แท็บระบบ จะมีปุ่ม **"ดึงอัปเดตโค้ดล่าสุด & รีสตาร์ทระบบ (Git Pull & Build)"** (ต้องใช้รหัส PIN แอดมิน) พร้อมไฟล์ `update-windows.bat` สำหรับกดรันที่หน้าเครื่องคอมพิวเตอร์
- **Visual Identity & Theme**:
  - คงเอกลักษณ์ Clean Enterprise Monitoring Dashboard โทนสี Slate / Royal Blue (`#2563EB`) และสีสถานะมาตรฐาน Emerald (`#16A34A`) สำหรับออนไลน์ และ Crimson (`#DC2626`) สำหรับออฟไลน์
  - แสดงเลข IP และ MAC Address ด้วยฟอนต์ Monospace (`font-mono tabular-nums`) ที่อ่านง่ายและเรียงหลักตรงกัน
- **Interactive Feedback & Motion**:
  - แสดง Toast แจ้งเตือนเมื่อตรวจพบและซิงก์เลข IP ใหม่จาก MAC Address สำเร็จ พร้อมแถบสถานะการสแกนแบบเรียลไทม์

### 3. Key Product Decisions & Trade-Offs

- **Decision 1: ระบบ Fast Background ARP Sweeper เฉพาะวง `10.80.80.*`**
  - *Chosen Approach*: ให้เซิร์ฟเวอร์กวาด Ping/ARP ช่วง `10.80.80.1 - 10.80.80.254` ด้วย Timeout สั้น (400ms) แบบขนานเบื้องหลังทุกๆ 15 วินาทีเมื่อมีอุปกรณ์ที่มี MAC Address สถานะเป็น OFFLINE และตรวจสอบตาราง ARP ทุกๆ รอบการ Ping (3–5 วินาที)
  - *Why*: แก้ปัญหาที่ Windows ไม่ยอมอัปเดตตาราง ARP ถ้ายังไม่ได้ส่งแพ็กเก็ตไปหา IP ใหม่ของจอ E-Board ทำให้ตรวจเจอจอเปิดใหม่ได้เองโดยไม่ต้องรอคนกดสแกน
  - *Alternatives Considered*: การรออ่าน `arp -a` อย่างเดียวโดยไม่กวาดวง `10.80.80.*` จะทำให้มองไม่เห็นจอที่ได้ IP ใหม่จาก DHCP จนกว่าจะมีคนกดสแกนเครือข่าย
- **Decision 2: ล็อกการจับคู่ด้วย MAC Address และกรองเฉพาะวง `10.80.80.*`**
  - *Chosen Approach*: ตรวจสอบ MAC Address แบบ Normalize (รองรับทั้งรูปแบบ `AA:BB:CC...`, `aa-bb-cc...`) และบังคับให้การอัปเดต IP อัตโนมัติรับเฉพาะ IP ที่ขึ้นต้นด้วย `10.80.80.` เท่านั้น
  - *Why*: ป้องกันไม่ให้ IP จากวงอื่น (เช่น VPN, Cloudflare WARP หรือการ์ดจำลอง) มาทับ IP จริงของจอ E-Board และป้องกันอุปกรณ์อื่นที่ไม่อยู่ในทะเบียนระบบเข้ามาปะปน
- **Decision 3: ระบบอัปเดตโค้ดเซิร์ฟเวอร์แบบไม่ทับฐานข้อมูลเดิม**
  - *Chosen Approach*: สร้าง API `/api/system/self-update` และสคริปต์ `update-windows.bat` ที่สำรองไฟล์ `devices.json`, `settings.json`, `logs.json` ไว้ก่อนเสมอ จากนั้นดึงโค้ดใหม่ สั่ง `npm run build` และ `pm2 restart eboard-monitor`
  - *Why*: เนื่องจาก AI Studio อยู่บน Cloud จึงไม่สามารถเขียนไฟล์ลงฮาร์ดดิสก์เครื่องคอมพิวเตอร์ในโรงเรียนได้โดยตรงหากไม่สั่งดึงข้อมูล วิธีนี้จึงช่วยให้กดอัปเดตได้ในคลิกเดียวโดยที่ข้อมูลอุปกรณ์และการตั้งค่าไม่หาย

- **Data Model & State**:
  - อุปกรณ์ใน `devices.json` ใช้ `macAddress` (Normalized 12-hex) เป็นคีย์หลักในการจับคู่กับตาราง ARP ของระบบเครือข่ายภายในวง `10.80.80.*`
  - เพิ่มตัวเลือกโหมดการสแกน `scanMode: 'registered_mac_only' | 'all_subnet'` ในหน้าต่างสแกนเครือข่าย โดยตั้งค่าเริ่มต้นเป็น `'registered_mac_only'` และล็อกช่วงเริ่มต้นเป็น `10.80.80.1` ถึง `10.80.80.254`
- **Interactive Component & State Mapping**:
  - **Auto Background Discovery**: เมื่อพบจอที่มี `macAddress` ออฟไลน์อยู่ เซิร์ฟเวอร์จะส่งคลื่น Ping กวาด `10.80.80.1 - 254` เบื้องหลังเพื่อกระตุ้น ARP Cache แล้วจับคู่ MAC ทันที หากพบว่าจอออนไลน์ที่ IP ใหม่ในวง `10.80.80.*` จะอัปเดต `device.ip` และเปลี่ยน `device.status = 'Online'` พร้อมบันทึกลง `devices.json` ทันที
  - **Manual MAC Scan (`SubnetScannerModal`)**: ผู้ใช้สามารถเลือกสแกนเฉพาะเครื่องที่มีในระบบ (คัดกรองด้วย MAC Address ในวง `10.80.80.*`) เพื่อดูสรุปว่าตอนนี้เครื่องไหนออนไลน์อยู่ที่ IP ใด และซิงก์อัปเดตได้ในคลิกเดียว
  - **1-Click Updater (`SettingsModal` & `update-windows.bat`)**: ปุ่มกดสั่งอัปเดตระบบผ่านหน้าเว็บสำหรับกรณีเชื่อม Git Repository หรือสคริปต์อัปเดตอัตโนมัติบน Windows ที่เก็บรักษาไฟล์ข้อมูลเดิมไว้ทั้งหมด
